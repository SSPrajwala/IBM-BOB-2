# DevPilot — Live Demo Script

A click-by-click presenter script for demoing the real web UI (not the slide video). Each section has **[do this]** — what to click — followed by what to say. Read the "say" lines in your own words; they're a starting point, not a word-for-word script.

Before you start: have `python3 webui.py` already running, and a second terminal/tab ready in case anything needs a restart. Open **http://localhost:8765** in the browser.

---

## 1. Intro (before touching anything)

**Say:**
"This is DevPilot — an AI developer-workflow copilot I built for the IBM Bob 2.0 hackathon. It takes one request — 'assess this project' — and fans it out to six subagents that run in parallel: onboarding, code review, testing, release readiness, modernization, and auto-fix. Everything you're about to see is a real, single-page app talking to a live local server — nothing here is a mockup."

---

## 2. Kick off a run

**[do this]** Leave "GitHub URL" selected (or click "Local folder path" if you're using a folder on disk). Paste the URL — e.g. `https://github.com/miguelgrinberg/microblog.git` — or the local path. Leave the PR-diff field blank. Click **Run DevPilot**.

**Say:**
"I'll point it at a real repo it's never seen before — not a seeded demo. Watch the log on the left: you'll see a pulsing LIVE badge while the six subagents report back, in parallel, in real time."

**[do this]** Let the log fill in for a few seconds, then point at it.

**Say:**
"Each of those six lines is a separate subagent finishing its own job — onboarding, review, testing, release, modernization, and auto-fix — not one script running top to bottom."

---

## 3. Full Report tab (the default view)

**[do this]** Once the run finishes, the **Full Report** tab is already active. Point at the health score gauge.

**Say:**
"The moment it lands, everything rolls up into one 0-to-100 health score with a plain-English executive summary — so you get the headline before you read a single table. Watch the number count up — that's not just a static image, it's a live-rendered dashboard."

---

## 4. New Developer tab

**[do this]** Click the **New Developer** tab.

**Say:**
"This is the onboarding view — an architecture map and a short list of starter tasks, generated by reading the source at the AST level, not just grepping filenames. A new engineer gets this instead of a day of unguided reading."

---

## 5. Reviewer tab

**[do this]** Click **Reviewer**.

**Say:**
"This is the code-review subagent's output — severity-ranked findings, from SQL injection to hardcoded secrets to unsafe deserialization. Anything flagged here that also has a failing generated test gets promoted to CONFIRMED — that's cross-agent corroboration, not just a static lint pass."

---

## 6. Tester tab

**Say:**
"Coverage gaps, plus pytest stubs DevPilot writes straight into the project's own tests folder — for the endpoints nobody's testing yet."

---

## 7. Release Manager tab

**Say:**
"A GO or NO-GO call with cited reasons — not a blank checklist someone can skip under deadline pressure."

---

## 8. Auto-Fix tab

**[do this]** Click **Auto-Fix**. Point at a diff preview.

**Say:**
"Every safe, mechanical fix DevPilot found gets a real diff preview right here — nothing is applied blind."

**[do this]** Click **Make it flawless — apply these fixes locally**.

**Say:**
"Clicking that doesn't apply anything yet — it opens a confirmation panel with the exact files and diffs."

**[do this]** Tick the checkbox **"I've reviewed the diff(s) above and want to apply them now."** — note the **Yes, apply these fixes now** button was disabled until you ticked it.

**Say:**
"Only once I explicitly confirm does it write the change, commit it to a local branch, and re-run the real test suite. It never pushes anywhere on its own — opening a pull request is a completely separate script that needs my own GitHub token, every time."

**[do this]** Click **Yes, apply these fixes now** and show the result (files changed + test pass/fail).

---

## 9. Blast Radius tab

**[do this]** Click **Blast Radius**.

**Say:**
"This is new this version, carried over from an earlier hackathon build. For the top findings, DevPilot searches the repo's real import graph for every file that depends on the buggy one — this diagram isn't a mockup, it's computed from the actual codebase. 'If this breaks, it takes N other files down with it.'"

---

## 10. Pre-Mortem tab

**[do this]** Click **Pre-Mortem**.

**Say:**
"For the same findings, a plain-English failure timeline — how the bug actually gets triggered, what happens next, and what it takes to prevent it. It's built from this run's own data, and can optionally be phrased by watsonx.ai."

---

## 11. Executive Intelligence tab

**[do this]** Click **Executive Intelligence**.

**Say:**
"This is the one-page view for leadership: health score, release call, hours saved, and a ranked risk portfolio. Notice what it doesn't do — it will not invent MTTR or MTBF numbers, because a static-analysis tool doesn't have real incident telemetry. It says so outright instead of dressing up a guess as a metric."

---

## 12. History tab

**[do this]** Click **History**.

**Say:**
"Every run against this exact project gets appended to a small local log — no database, just JSON. So you get a score trend over time, and — just as important — which rules keep recurring across runs. A finding once is a bug; a finding every run is an architectural weakness."

---

## 13. Dependency Map tab

**[do this]** Click **Dependency Map**.

**Say:**
"This takes the same reverse-dependency scan behind Blast Radius and runs it across the whole repository — every module's real import relationships, as a chord diagram."

---

## 14. Ask DevPilot tab

**[do this]** Click **Ask DevPilot**. Click into the input field, type a question — e.g. *"is this safe to ship?"* or *"what should I fix first?"* — and click **Ask**.

**Say:**
"This is live, not a fixed FAQ — it's answering from this run's actual report. It falls back to deterministic, templated logic when watsonx.ai isn't configured, and calls a real watsonx.ai client once IBM Cloud Lite credits are available — same fallback path either way."

---

## 15. Demo Video tab

**[do this]** Click **Demo Video**.

**Say:**
"And this tab is exactly how you're watching this walkthrough right now — drop an mp4 next to the app and it plays natively, with real seek and scrub support, no extra setup."

---

## 16. Close

**Say:**
"Five workflows that are normally manual and disconnected — onboarding, review, testing, release, modernization — running in parallel, cross-checking each other, and rolled into one report a human can act on immediately. Built end-to-end on IBM Bob 2.0."
